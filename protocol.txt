1. Introduction 
This  document  outlines  the  communication  protocol  implemented  in  the  device  for  seamless 
integration  with  a  platform.  The  protocol  facilitates  bidirectional  communication,  allowing  the 
device  to send  outbound  messages  to  the  server  and  receive  inbound  messages  in  return,  all 
transmitted  via a wireless channel.  
Device communication to platform based on the following points. 
- Outbound messages - Outbound messages refer to data transmissions  originating from 
the  device  and  destined  for  the  server.  These  messages   serve  to  convey  crucial 
information,  updates, or requests from the device to the integrated platform. 
- Inbound messages - Inbound messages refer to data transmissions  originating from the 
server   and   destined   for  the   device.   These   messages   provide   essential   updates, 
commands,  or configurations  to the  device,  allowing  seamless  communication  between 
the server and the integrated platform. 
2. Intended audience 
This  document  is  intended  for  reference  for direct  customers,  system  integrators who  wish  to 
integrate the device with their platform. 
3. TS101 PLUS-4G Data Format 
The device sends the following information  packets to the server/SMS. All the packets which will 
be sent to the server are as per NMEA standard. 
2 types of communication occur between the device and the outside world. 
 
1. Outbound Communication: 
 
• Login: Initiates the communication  session between  the device and the server. 
• Tracking: Regularly transmits the device's  current location and related information. 
• Health Monitoring:  Sends data related to the health and status of the device. 
• Emergency:  Signals an emergency situation  from the device to the server. 
• Emergency SMS: Sends emergency  alerts via SMS. 
• Maintenance:  Communicates  maintenance-related  information. 
• Command  Response: Responds  to commands  initiated by the server. 
• CAN Packet: Sends vehicle ECU Controller  Area Network  (CAN) packets. 
 
2. Inbound Communication: 
 
• GPRS Based Commands:  Allows the server to send OTA commands to the device over 
the General Packet Radio Service (GPRS). 
• SMS Based Commands:  Enables to send commands  to the device via Short Message 
Service (SMS).

5. Login Packet 
The login packet serves as an establishment  of a successful connection between the device and 
the  server.  Also,  initiates  and  authenticates  immediately  after  the  connection  establishment  is 
successful.

servers. 
The  login  packet  is  sent  to  initiate  and  authenticate  the  communication  session  between  the 
device and the server.  It signals  that the device  is active  and ready to transmit  and receive data

6 Primary and Secondary Server Tracking Packet 
The Government  of India has designed an Intelligent Transport Systems (ITS) under Automotive 
Industry  Standard-140  to  increase  the  safety  of  passengers  and  ensure  the  efficiency  of  the 
transport  system. The  regular  tracking  packet  contains  location  information  and  other  required 
information as per AIS140 standard.  
The  location Packet  will  be  sent to  both primary and  secondary  servers. Contains  location 
information  and  other  essential  data  as  mandated  by  the  AIS140  standard.  sent  exclusively  to 
the primary or secondary server, as defined  in the server configuration.  
6.1 Primary Server Protocol  Format 
The regular tracking packet contains location information and other required information as 
per the AIS140 standard. Based on the number of packets available for sending the data, the 
device will can either single tracking packet or the multiple tracking packet to the server.

9.4 RS485  
Recommended  Standard  485,  is  a  standard  defining  the  electrical  characteristics  of  a  digital 
signaling circuit for serial communication. It is widely used for communication  over long distances 
in  various  applications  such  as  industrial  automation,  process control,  and  data  acquisition. 
RS485  supports  multiple  devices  on  a  single  communication  line,  making  it  suitable  for  multi-
point and multi-drop  configurations.

9.5 RS485 Packet Format 
RS485 supports  a multi-point  configuration,  meaning that multiple  devices can be connected  on 
the  same  communication  line.  Each  device  has  a  unique  address,  and  communication  can  be 
initiated by any device on the network. This makes RS485 suitable for multidrop networks where 
multiple devices share the same communication  line.

12   Inbound Communication  
The  inbound  communication  will happen  from  the  outside  world  to  the device.  In this  category, 
only GPRS command will be sent from the server to device. 
The command  can be executed  with a single  key in place or multiple  keys in a single  command 
structure.  
 
12.1 Single Key Config Parameters 
The  single  key  can  be  sent  to  the  device  to  configure  as  per  the  requirement.  The  command 
should  be  pushed  on  the  same  socket  on  which  the  device  is  sending  the  data  to  the  server. 
Please refer to the User manual to build the packet as per the requirement.  
12.2 Sample Packet  
$1234,358250330001255,aquila123,set,114:ms1.aquilatrack.com*43
